Short answer: yes to both, and you can do it cleanly in Tkinter without killing performance—just don’t fight the event loop.

A) Transparent, draggable overlays (circles, etc.)

Tkinter actually makes this pretty workable if you use a Canvas on the second monitor.

Core idea
Display your base image on a Canvas
Draw overlays (circle, rectangle, etc.) as canvas items
Use:
stipple (simple transparency)
or a semi-transparent image (better-looking)
Bind mouse events to move them
Minimal example (circle overlay you can drag)
import tkinter as tk
from PIL import Image, ImageTk

class OverlayDemo:
    def __init__(self, root, image_path):
        self.root = root

        # Second window (your player screen)
        self.display = tk.Toplevel(root)
        self.display.geometry("+1920+0")  # adjust for your 2nd monitor

        self.canvas = tk.Canvas(self.display, bg="black")
        self.canvas.pack(fill="both", expand=True)

        # Load base image
        self.img = Image.open(image_path)
        self.tk_img = ImageTk.PhotoImage(self.img)

        self.image_id = self.canvas.create_image(0, 0, anchor="nw", image=self.tk_img)

        self.current_overlay = None

        # Drag state
        self.drag_data = {"x": 0, "y": 0, "item": None}

        self.canvas.tag_bind("overlay", "<ButtonPress-1>", self.start_drag)
        self.canvas.tag_bind("overlay", "<B1-Motion>", self.drag)

    def add_circle_overlay(self):
        r = 80
        x, y = 200, 200

        self.current_overlay = self.canvas.create_oval(
            x - r, y - r, x + r, y + r,
            fill="red",
            stipple="gray50",   # fake transparency
            outline=""
        )

        self.canvas.addtag_withtag("overlay", self.current_overlay)

    def start_drag(self, event):
        item = self.canvas.find_closest(event.x, event.y)[0]
        self.drag_data["item"] = item
        self.drag_data["x"] = event.x
        self.drag_data["y"] = event.y

    def drag(self, event):
        dx = event.x - self.drag_data["x"]
        dy = event.y - self.drag_data["y"]

        self.canvas.move(self.drag_data["item"], dx, dy)

        self.drag_data["x"] = event.x
        self.drag_data["y"] = event.y


root = tk.Tk()
app = OverlayDemo(root, "map.png")

btn = tk.Button(root, text="Add Circle", command=app.add_circle_overlay)
btn.pack()

root.mainloop()
Notes that matter
stipple="gray50" = cheap transparency
(not pretty, but fast and built-in)
If you want real alpha transparency:
create a transparent PNG circle using Pillow
place it with create_image()
that looks much better
You can tag multiple overlays ("overlay") and manage them easily
B) Auto-reloading image when file changes

Yes—but don’t block Tkinter. Use after() instead of loops or sleeps.

Simple, efficient file watcher (polling)
import os
import time

def watch_file(self, path):
    self.last_mtime = os.path.getmtime(path)

    def check():
        try:
            mtime = os.path.getmtime(path)
            if mtime != self.last_mtime:
                self.last_mtime = mtime
                self.reload_image(path)
        except FileNotFoundError:
            pass

        self.root.after(1000, check)  # check every 1 sec

    check()
Reload function
def reload_image(self, path):
    from PIL import Image, ImageTk

    self.img = Image.open(path)
    self.tk_img = ImageTk.PhotoImage(self.img)

    self.canvas.itemconfig(self.image_id, image=self.tk_img)
Why this won’t slow Tkinter
after() schedules work inside Tkinter’s event loop
No threads needed
Checking mtime is extremely cheap
500–1000 ms interval is plenty
If you want instant updates

You could use:

watchdog (filesystem events)

But honestly:

polling every 0.5–1s is simpler and rock solid across Fedora / Windows / ChromeOS
Practical advice for your D&D setup
Use Canvas overlays for:
spell areas
fog-of-war markers
tokens
Use tags like:
"token"
"aoe"
"fog"
Keep overlays separate from the base image so reloads don’t wipe them
One important gotcha

When you reload the base image:

don’t recreate the canvas
just update the image item

Otherwise you’ll lose overlays.
